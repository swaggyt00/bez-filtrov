# v0.8 Competitor-Grounded Content Rebuild — Design Spec

## Goal
Rebuild the game’s card corpus so the app has enough depth for repeated sessions and the card copy is grounded in proven public competitor patterns instead of being authored from a blank page.

The existing product shell, scenario flow, Seduction visual system, persistence, duration mechanics, skip/re-roll behavior, and role-aware selection engine remain intact unless a content requirement forces a minimal engine change.

## Core release rule
v0.8 is a content release first.

Every new card must be traceable to an approved public competitor source or public competitor pattern. The implementation may adapt wording, names, target perspective, heat, duration, player count, and role semantics so the card works correctly in Без Фильтров, but it must not be invented from an empty prompt.

Do not bulk-copy protected competitor wording verbatim. Use public competitor material as the source corpus and preserve the useful mechanic, tension, choice, reveal, or action while rewriting the final Russian card for this app.

## Source strategy
Build a research corpus from public competitor pages and publicly accessible card banks. Initial approved source families include:
- The Foreplay Game
- Smush
- Wargamer
- Xdares
- Spiced Couple
- additional public adult Truth-or-Dare / couples-game banks discovered during implementation when they meet the same quality bar

A source registry must live in the repository. Every authored v0.8 card must carry an internal source reference or source-pattern reference that can be validated by the audit. The production UI does not need to display this metadata.

The source registry exists for provenance and editorial discipline: it must be possible to answer “what public competitor pattern did this card come from?” without storing wholesale copies of competitor pages in the repository.

## Perspective contract
The v0.7 perspective failures are release-blocking in v0.8.

### Truth
The player whose turn is shown at the top is always the person who answers.

A Truth must be understandable when read directly to that player. It must not silently switch to the opponent’s first-person voice.

Bad pattern:
- a card shown to Рада says `Что я делаю, что для тебя выглядит как флирт?`

Good pattern:
- `Что Максим иногда делает с другими людьми, что тебе кажется флиртом?`
- or a target-independent equivalent when the card does not need a specific target.

### Dare
A Dare is always an instruction from the game to the current player.

Bad pattern:
- a card shown to Рада says `Поцелуй меня в шею.`

Good pattern:
- `Поцелуй Максима в шею.`

When another player is required, render that player’s name explicitly or use an unambiguous target placeholder that resolves to the name before display.

### First-person ban
Authored runtime card copy must not use opponent-voice first-person forms such as `я`, `меня`, `мне`, `мой/моя/моё/мои` unless the card explicitly asks the current player to say a quoted phrase and the first person belongs to that quoted phrase.

The content audit must flag these cases for manual review.

## Editorial standard
- natural spoken Russian;
- short enough to read immediately on a phone;
- one clear reveal, choice, confession, challenge, or action per card;
- no questionnaire/corporate tone;
- no meaningless wrappers such as `в теме`, `на тему`, `если говорить про`, `идеальный сценарий на тему`;
- no dangling `это`, `такое`, `так`, `этот вариант` without a referent in the same card;
- Truth must produce an answer worth hearing;
- Dare must produce an observable action;
- speaking-only Dares are allowed only when the speech itself is the social performance;
- persistent effects must state when they end;
- heat increases intensity, not verbosity;
- direct adult terminology is allowed in Sex mode;
- Sex / Hard may be explicit but scenes remain bounded and consensual;
- alcohol remains separate from sexual consent;
- no dangerous drinking requirements.

## Diversity rules
The larger deck must not be padded with cosmetic variants of the same idea.

Within each scenario × heat × type bucket:
- no exact duplicate text;
- no duplicate normalized core idea above the allowed threshold;
- cap repeated interaction families so one mechanic cannot dominate the bucket;
- avoid repeated opening templates across adjacent cards;
- competitor-source coverage should be mixed rather than one source dominating an entire bucket.

Existing `coreIdea` and `interaction` metadata should be retained or strengthened to support this audit and runtime anti-repeat behavior.

## Runtime behavior
No runtime AI generation.

Cards remain authored data selected by the existing engine. Existing target eligibility, gender semantics, pairing preferences, min-player rules, duration rendering, and persistence continue to apply.

If source-grounded cards require additional semantic metadata, add only the minimum fields necessary to represent them correctly.

## QA — no TinyFish
TinyFish is explicitly excluded from v0.8 release QA.

Release verification uses deterministic automated checks only, plus direct source/editorial review during authoring.

### Content audit
Extend `scripts/audit-cards.ts` to verify at minimum:
- exact total of 1,440 authored cards;
- exact bucket counts from this spec;
- source/source-pattern reference exists for every v0.8 card;
- no exact duplicate text;
- no unresolved placeholders;
- perspective first-person violations are flagged;
- target-required cards have valid target semantics;
- Truth/Dare classification remains semantically correct;
- vague/AI-style banned patterns remain blocked;
- persistent Dares have clear endpoints;
- role/gender/min-player semantics remain valid;
- two-player Afterdark still has a healthy eligible pool at every heat/type.

### Unit/data tests
Expand deck tests to cover:
- perspective rendering fixtures with named actor and target;
- current player remains the answerer for Truth;
- current player remains the actor for Dare;
- target names resolve exactly once;
- persisted rendered text does not change after resume;
- duration placeholders resolve once and stay stable;
- bucket/source counts.

### Playwright E2E
Add deterministic browser tests for the actual UI flow instead of using TinyFish.

At minimum cover:
- age gate → setup → game;
- Couple M+F starts;
- Sex M+F starts;
- Party rejects 2 and starts with 3;
- Afterdark starts with 2;
- revealed card has no unresolved target/duration placeholders;
- resume restores the exact rendered card text;
- choice heading has accessible text `Правда или действие?`;
- mobile viewport around 390×844 has no horizontal overflow or clipped primary controls.

Tests must be stable enough to run in CI before deploy.

## Deployment gate
Do not merge/deploy v0.8 until:
1. content audit passes;
2. deck/unit tests pass;
3. Playwright E2E passes;
4. production build passes;
5. a final bucket-count/source-coverage report is produced and reviewed.

No TinyFish run is part of the release gate.

## Out of scope
- visual redesign;
- new game modes;
- analytics/PostHog;
- accounts/backend/cloud sync;
- runtime LLM card generation;
- copying an entire paid/private competitor deck verbatim;
- unrelated refactors.
